# 浮层样式与共享数据：公开技术示例

这是从实际排障方法抽象出的示例，已去除私人项目名称、提交号、托管标识、路径和用户数据。不是对特定产品或当前发布状态的声明，也没有声称所有故障均已复现。

## 祖先 CSS 选择器跨不过 Portal

假设会员页面在 `.member-route` 容器内，旧规则是 `.member-dialog ...`。为了隔离两套页面，开发者把它批量改成 `.member-route .member-dialog ...`。

如果 Dialog 或 Popover 通过 Portal 挂到 `document.body`，浮层就没有 `.member-route` 祖先，新规则无法匹配。复制相同的组件源码不代表布局和主题相同，祖先主题变量也不会自然跨越挂载边界。

检查真实 DOM、计算样式和组件库的容器配置。根据当前组件 API 选择明确的浮层容器、样式标记或独立样式方案，并实际打开选择框、保存、重开，检查暗色和窄屏。仅首页返回 HTTP 200 或构建通过发现不了这一类问题。

## 两种体验可能保存了两份数据

如果旧入口继续使用账号同步，而新入口改用独立本地存储，它们就不能被默认描述为一个已完成整合的产品。需要确认身份、稳定 ID、共享与独立记录、刷新恢复、删除语义，以及跨入口修改能否读回。

把源业务测试一并带到目标，同时保留目标已有的有效安全和同步检查。不要为了文件树相同删除有效检查。源码发布也不等于个人数据已经迁入账号。

## 验证与结论的边界

对同一条流程分别记录：源应用预期、目标实际结果、证据和缺口。必要时覆盖打开弹窗、选中、保存、重开、切换入口、刷新和图片读回。静态源码只能证明结构和可能机制；浏览器操作、真实账号、离线和真机结果应按实际完成程度报告。

跨平台迁移应保留业务结果与数据语义，先验证一条完整路径，不能由“同平台完整复制更可靠”推导出“小程序直接复制网页源码即可”。
